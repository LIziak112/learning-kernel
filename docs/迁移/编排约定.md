# 全量迁移派单与验收

这是 M00–M14 专用的协作方式，不改变两仓各自的编码、测试和提交规范，也不自动开工。模型名按实际工具核对：主会话选择 `gpt-6.2-astra`，实现者显式指定 `gpt-6.2-sol`。SOL 默认 `reasoning_effort=high`，只有共享契约、并发事务、迁移序列和跨库恢复这几类工单用 `xhigh`。提示词不会更换正在运行的主模型。指定模型、工作区权限或子任务工具不可用时，说明缺少哪项，停止相应派单，请负责人决定；不得声称已切换或擅自降级。

2026-11-22 修订的起因：上一轮主控把每个行为都按发布级验收处理（逐单全量、逐单变异审计、反复取临时检出），又把 281 KB 的单个 Markdown 台账当作唯一状态机反复打补丁，SOL 也只派不收；据两个主控线程的复盘反馈，其中一个线程派生了 55 个子 Agent，上下文超过 450K。下面每条规则都针对其中一个问题。

## 一个主控，一份短台账

- 同一时刻只有一个主控。开工在[台账恢复点](兼容台账.md#恢复点)的「当前主控」一行登记，结束时清掉。看到别的主控在册就停下问负责人，不并行开第二个主控。
- 台账只写结论：一个 ID 一行，加「在办」「待决」两张小表。派单、回执、复核的细节写进 `工单/<工单号>.md`，每单一个文件，只往末尾追加。台账改动用整行替换，补丁失败就重读该行，不写脚本修补，也不整份重写。
- 历史台账（`兼容台账-历史至20261122.md`）只读。按 ID、SHA 用 `grep` 定位后读相关段落，不整份读入。

## 什么时候派，什么时候不派

- 本轮唯一目标是 [OwnClass M00–M14](总清单.md)。每单从台账领取，绑定已冻结的产品行为。已验行为按[复查计划](已验收行为架构复查.md)的触发条件补验。
- 架构条款用于裁决当前行为与验收边界。只有具体 OwnClass 行为暴露公共契约缺口，并能用宿主无关的失败用例证明时，才给内核派实现单。颉斌斌英语阅读 demo 留待负责人单独立项，不占本轮工单或放行条件。
- 派单单位是[验收分批](验收分批.md)里的一个子组：同一夹具、同一写集下的 3–10 个 ID 一单，不按单个 ID、文件、命令或提交拆单。未厘清输入输出的子组先由主控澄清，不能把整个 M 包扔给执行者探索。
- 主控自己做、不派 SOL 的三类事：台账与文档；合计不超过 20 行且不动测试断言的返修；按 CI 报错修 lint、类型。只需作决策或核对一个事实时也不派单。不要为了“有个审查者”逐提交再开一个 Agent。

## SOL 的数量和生命周期

- 同时在办最多 2 个 SOL；第二个只在两单写集不相交、验收独立、互不等待时开。共享 schema、迁移序列、生成产物或同一数据库夹具一律串行。不层层再派。
- 一个主控会话累计最多派 8 个 SOL。派满后写恢复点、结束会话，由负责人新开主控接续。
- SOL 交付、主控复核后**必须立即关闭**，不留作备用。同一单的返修交回原 SOL；原 SOL 已关闭就新开一个，只给返修需要的失败用例和文件定位。
- 新 SOL 不继承对话（工具支持时 `fork_context=false`）。只给当前工单、目标仓规则和必要定位，不附台账、旧聊天或长日志。SOL 不写台账、不改范围、不放宽门禁；主控不与它同时改同一文件。

## 派单与回执

派单按[工单说明](工单/README.md)的格式写：覆盖 ID、仓根与基线 SHA、允许写集、数据副本、已有旧侧证据、待证行为与反例、L1 验收命令、墙钟预算（默认 3 小时）和交付分支。派出前确认执行者可写、主控可取回改动；文件边界变化先回报，不先改后报。

涉及存量数据的派单附上实际备份的定位和该单工作副本。按[启动提示词](启动提示词.md)可下载并使用整库及真实附件，无需脱敏。两名执行者各用自己的写副本；一张单只有一份写副本、一棵 worktree，放在固定目录，不放 `%TEMP%`，同一场景续用，工单关闭时删掉。

SOL 正常只在单末回一次，最多五行：① ID、结论（待主控复核）；② 提交号与远端分支、基线、`git diff --stat`；③ 关键红测及失败原因；④ 实际绿测命令、用例数、CI 链接；⑤ 风险／未测。不贴 diff、完整日志、思考过程或逐命令进度。

只有数据或权限风险、规格冲突、写集碰撞、需外部授权、超出墙钟预算，或同一前提两次修复仍失败时，立即停相关写入并发一条：`阻断 ID｜事实/证据｜影响｜建议与所需决定`。主控同一阻断只升级一次，记入台账「待决」。禁止静默绕过；正常成功也不得隐藏未测项。

## 三级验收

| 级别 | 什么时候 | 跑什么 | 不跑什么 |
| --- | --- | --- | --- |
| L1 工单 | 每张单 | 定向红测→绿测；触及文件的 `test:affected`、`e2e:affected`；内核单按仓规跑一次 `pnpm run verify` | 本地产品全量、覆盖率／CRAP／重复／变异审计、干净检出、合成变异用例 |
| L2 批 | 每批收口一次 | 固定累计候选（一批只换一次内核包）；完整 diff 先简化、再做一次正确性审查；推送后该候选的一次绿 CI | 逐提交审查；在 CI 之外再跑一遍本地全量 |
| L3 包 | 每个 M 包收口，或 PR 转正式评审前 | 覆盖率、CRAP、重复、变异审计（内核按 ub-mode，产品按产品仓 AGENTS.md，仓规没要求的不做）；干净检出安装验收；已有待判变异统一判读，判不了的记剩余风险 | — |

- 产品选测命中强制全量（`pnpm-lock.yaml`、`packages/contract`、迁移、schema、`scripts/` 等），本地不补跑。推到工单分支，由产品 CI（`.github/workflows/ci.yml`）跑全量；CI 失败只按失败用例定向修。
- 复用证据：同一 SHA 上同一命令的结果直接复用；SHA 变了只重跑 diff 触及的用例；正在运行的同一轮直接等结果。
- 主控复核只看回执、`git diff --stat`、与风险相关的关键文件和 CI 结果，不重跑 SOL 已跑过的同 SHA 命令。证据齐备才记通过；待 CI、真机或授权的，注明已验部分与恢复条件，记 `待 CI`。

## 收口和恢复

M04 的 P4/P5 用同一真实单选卷串起读取、公布和恢复，已在历史台账通过。批末交接先写本批打通的产品行为、剩余放行阻断及其归属，其他题型的差异归回对应 M 包。

够了就停：工单写明的 ID、反例和验收命令都通过就交付；途中发现的别的差异登记到对应 ID 或「待决」，不并进本单。

主控只在依赖结果时等待，不催更、不建后台定时任务；空档只做不重叠的工作。每批收口后整节重写恢复点（限 15 行）。主控会话派满 8 个 SOL、上下文约 200K tokens 以上，或一个 M 包收口时，写好恢复点、清掉「当前主控」，结束会话。换会话先核对台账在办行、执行者状态、工作区和交付物：能续则续，已交付则复核，确认原单无人执行后才重新派发。局部阻断不影响其他已授权且依赖满足的工单；若无可安全推进项，只上报所需决定。对负责人仅报批次结果、实证、风险和下一动作。
