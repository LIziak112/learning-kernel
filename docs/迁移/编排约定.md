# 全量迁移派单与验收

这是 M00–M14 专用的协作方式，不改变两仓各自的编码、测试和提交规范，也不自动开工。模型名按实际工具核对：主会话选择 `gpt-6.2-astra`（建议 xhigh），实现者显式指定 `gpt-6.2-sol`（默认显式传 reasoning_effort=xhigh）。提示词不会更换正在运行的主模型。指定模型、工作区权限或子任务工具不可用时，说明缺少哪项，停止相应派单，请负责人决定；不得声称已切换或擅自降级。

## 什么时候派，什么时候不派

- 本轮唯一目标是 [OwnClass M00–M14](总清单.md)。每单绑定已冻结的产品行为或原在办工单，从[台账恢复点](兼容台账.md#恢复点)领取。新主控接管后，旧主控保持暂停；同一工单只保留一名写入者。已验行为按[复查计划](已验收行为架构复查.md)的触发条件补验。
- 架构条款用于裁决当前行为与验收边界。只有具体 OwnClass 行为暴露公共契约缺口，并能用宿主无关的失败用例证明时，才给内核派实现单。已有两步阅读与两次原答跨重开的用例继续随内核门禁运行。颉斌斌英语阅读 demo 的练法、页面、历史导入和切换留待负责人单独立项，不占本轮工单或放行条件。
- Astra 负责行为边界、反例、两仓归属、依赖顺序、风险决定、批末 diff 和最终验收；实际代码、测试和修复交给 SOL。只需作决策、核对一个事实、整理台账或修改计划，主控自己做。不要为了“有个审查者”逐提交再开一个 Agent。
- 默认同时只有一个 SOL。按一个可独立验证的行为派单，包含红测、实现、目标回归和必要返修；不按文件、命令或提交拆单。同一行为的追问、回归和返修优先交回原 SOL。Astra 验收并将证据记入台账后，若下一行为有独立的输入、写集和验收条件，不依赖上一单未交接的判断，可关闭原 SOL，再用新 SOL 接下一单，即使两单属于同一里程碑。并发上限约束同时在办的人数，不限制先后接手的人数。未厘清输入输出的任务先由 Astra 澄清，不能把整个 M 包扔给执行者探索。
- 仅当两项有独立验收、写集不相交、互不等待且有明确并行收益，才允许第二个 SOL；全局最多两个，不层层再派。共享 schema、迁移序列、生成产物或同一数据库夹具一律先串行。跨仓先验公共契约再接固定产物，不并发猜接口。
- 新执行者默认不继承整段对话（工具支持时 `fork_context=false`）。只给当前工单、目标仓规则和必要专题/证据定位，不附全量台账、旧聊天或长日志。SOL 不写总台账、不改范围、不放宽门禁；主控不与它同时改同一文件。

## 派单与回执（可直接复制）

工单：`M/行为ID｜实际仓根、工作区、分支、基线 SHA 和允许写集｜交付方式（本地提交或基于该 SHA 的可定位 diff）｜旧侧证据与待证行为｜失败/负例｜目标命令和验收条件`。派出前确认执行者可写、主控可取回改动；文件边界变化先回报，不先改后报。一个行为的正常、失败和重试场景可分别入账，但不因此拆成三张工单。

涉及存量数据的派单附上实际备份的定位和该单工作副本。按[启动提示词](启动提示词.md)可下载并使用整库及真实附件，无需脱敏，也可在服务器的独立实例上运行。两名执行者各用自己的写副本。内核独立构建及测试继续按仓根规则验收。

正常只在批末回一次，最多五行：① ID、结论（待主控复核）；② 可取回的提交号或工作区、基线及 diff 定位（含新增文件），不能只报文件名；③ 关键红测及失败原因；④ 实际绿测命令、用例数、证据位置；⑤ 风险／未测。只给摘要，不贴 diff、完整日志、思考过程或逐命令进度。长证据留在测试报告或工作数据目录，交接引用位置、摘要和差异即可。

只有数据或权限风险、规格冲突、写集碰撞、需外部授权或同一前提两次修复仍失败时，立即停相关写入并发一条：`阻断 ID｜事实/证据｜影响｜建议与所需决定`。主控同一阻断只升级一次。禁止静默绕过；正常成功也不得隐藏未测项。

## 监控、收口和恢复

产品小步开发跑当前行为的定向用例。能一起验收的改动固定到同一累计候选，按产品选测规则执行所需门禁，包括自动升级的全量。主控与 SOL 共用同一轮结果；已有同 SHA、同范围、同环境的验证在运行时，等它返回。内核仍按仓规逐项运行 `pnpm run verify`。

M04 的 P4/P5 用同一真实单选卷串起读取、公布和恢复。批末交接先写本批打通的产品行为、剩余放行阻断及其归属。其他题型的差异归回对应 M 包。需要准备下一题型时，先查 M05 已有旧侧证据；有空闲 SOL 且写集独立时才补缺项。

派单时主控在[兼容台账](兼容台账.md)登记在办、执行者及写集；收到交付记待复核，不等验收通过才首次登记。主控在目标工作区确认落地的是所报改动，然后检查 diff、负例和集成证据。SOL 跑目标测试；相同修订、夹具、环境、命令及断言的可信结果不机械再跑，任何条件改变或证据不可信则重验，两仓必跑门禁不省略。失败退回原工单；待 CI／真机／授权注明已验部分与恢复条件，不视为返工或通过。证据齐备才记通过。

主控只在依赖结果时等待，不催更、不建后台定时任务；空档只做不重叠的工作。换会话先核对台账活动工单、执行者状态、工作区和交付物：能续则续，已交付则复核，确认原单无人执行后才重新派发。局部阻断不影响其他已授权且依赖满足的工单；若无可安全推进项，只上报所需决定。对负责人仅报批次结果、实证、风险和下一动作。
