## 同一作业的旧侧实测

从固定源码导入 `samples/v2/练习样例.md` 首单元，经教师 API 建立两个合成学生，将八题作业只布置给学生甲，设置 `answerRelease=after_due`，`dueAt=2099-01-01T00:00:00.000Z`。学生甲登录，通过 `POST /api/student/assignments/:id/attempt` 开卷。所有请求通过 `createApp().request` 进入产品路由。SQLite 文件由产品迁移后的测试模板生成，草稿正文落入该次运行的独立临时 `dataDir`。

- 整卷入口 `POST /api/student/attempts/:id/submit` 装配见 `apps/server/src/routes/student-batch-submission.ts`。此前通过 `PUT /api/student/attempts/:id/answers/:qid` 将 `练习四-1` 的判断答案从 `false` 更新为 `true`，答案版本 `1 → 2`。通过同卷 `PUT /notes/:qid` 上传 1 笔稿，再按 `baseRevision=1` 上传 3 笔稿，草稿头 `1 → 2`。
- 提交 JSON `revisions` 有八项，每项含 `questionId`、从学生草稿详情读到的 `questionRevisionId` 和 `expectedAnswerRevision`。`evidence` 有八项，`练习四-1` 声明 `state=frozen`、第二次草稿回执的 `versionId`、`revision=2`，其余七题均 `state=none`。该次合成卷 ID 为 `a4d86df0-6f84-407f-8812-95350c7fcc56`，目标题冻结行 ID 为 `a803ee25-31bf-4d51-93c9-d4be1fd244bc`，封存版本为 `ec869497-1627-48e6-8967-1ab61347f995`。成功及重发两次使用同一串 JSON 字节，SHA-256 为 `35cbcbbd5e4c76a3ff7e92f6187b3d2d0628d1cc8c112d4fed7b686fdb495e2a`。

if ($LASTEXITCODE -ne 0) { throw '产品克隆失败' }
