## 最小人工链路

`/t/students` 在 `apps/web/src/App.tsx:115,170` 由 `TeacherLayout` 挂载 `StudentsPage`。布局先读教师会话，个人账号进入旧教师布局时走个人管理地址转换。普通未登录状态经 `PortalGuard.tsx:31` 走 `/t/login?returnTo=...`，带原路径、查询与片段。页面通过 `StudentsPage.tsx:78`、`features/students/student-queries.ts:23` 和 `portals/clients/students-client.ts:18` 发起名单查询。

服务端由 `apps/server/src/app.ts:288` 挂 `/api/teacher`，由 `routes/teacher.ts:116,231` 先装配 `requireTeacher` 再装配 `teacher-students`。守卫使用教师 Cookie，`routes/teacher-students.ts:44` 再解码 `includeArchived`。名单服务在 `services/student-service.ts:197` 按会话教师 ID 查询，默认排除归档，按最近作答降序排列，缺少活动时间的学生在末尾。MCP 同行为 ID 的 `list_students` 默认含归档，字段是 MCP 自己的摘要。

独立合成内存库通过 `createApp().request` 观察到匿名与学生 Cookie 均为 `401 UNAUTHORIZED`，教师空名单为 `200` 加空数组，插入一名本域学生后仅返回该 ID，非法 `includeArchived` 为 `400 VALIDATION_ERROR`。个人双会话在同一夹具中查询教师和学生作业列表分别得到 `200` 和空数组，教师名单查询只返回绑定学习者。个人门户没有班级作业与班级学生名单页。HTTP 仍经过通用角色守卫和对象作用域，个人门户的缺页与 HTTP 会话的可达性分别记录。个人端的 `/p/manage/students/:id` 则只接受绑定学习者 ID，其他 ID 回个人数据页。

同版本整卷提交的封存、拒绝和重发补证见[交卷封存](交卷封存.md)。原字节重发该合成卷的正式 `POST /api/student/attempts/:id/submit` 得到 `409 ALREADY_SUBMITTED`，且无第二份交卷事实。分段上传的 finish 是独立入口，待取证。同一个逐题 HTTP 路由分支分别调用普通练习与讲练提交，MCP 的 `student_submit_practice_question` 调用普通练习 `commitPracticeQuestion`。

作业列表、预检查、布置、编辑和删除归 M04。班级作业资格沿用角色与名册作用域，关联 M01。删除使用同一行为 ID 并保留出口差异。MCP 确认删除前额外拒绝已有人开始的作业，教师 HTTP 的软删函数按作业归属执行，保留历史作答。
