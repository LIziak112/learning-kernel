## 如何开始

1. **先接现有工作。** 解答、应用、找错现已合到产品累计候选 `2d3a2cd9`。沿用 K18 和解答题的迟到写、跨库中断、原件恢复证据。应用和找错从原入口核各自的题型登记、冻结策略与回读，缺少真实非空旧样本的覆盖注明合成证据。复用已启动的累计门禁。开放题只写标题的差异另按该题型的已答规则定向验。
2. **下一条关键路径是实际判定写入。** 用一份已走新链的混合卷，把学生自评、教师批改和已判回读接起来。已有教师改判 503 的反例可以直接接回原工单。有这份结果后，记录、学情和导出复用它。纯阅读、真实历史升级和独立浏览器保稿场景可各用独立副本先行。
3. **典型场景预先固定。** 一份正式混合作业、一份含材料及逐题作答的讲练、一份纯讲义，另用一份完整真实备份做升级和灾备。选取必要的包含关系、未公布状态、题目版本、作品和角色。历史、真机、跨设备和 AI 任务状态各保有可追溯的证据。需要互斥写入或从同一状态重放时，分出独立副本。

## 如何用同一轮证据覆盖多个行为

- **先按边界确定代表用例。** 在测试层声明期望，随后把真实页面、HTTP、MCP 或导出链接到同一份已冻结业务事实。允许共用账号、题目、作品与快照；跨角色、并发和恢复仍用独立会话、写副本和可重复截面。
- **旧侧证据按条件失效。** 交接记录固定旧 SHA、候选 SHA／包摘要、夹具及其初始状态、运行环境、命令与断言。旧基线和夹具不变时复用旧侧记录；输入形态、授权、运行分支或断言发生影响时补该场景。换候选时核查相关读写与依赖差异，及时执行仓规要求的门禁。
- **一个 ID 一条可定位结果。** 可引用同一个日志或测试名称的不同断言，保留必要的拒绝、持久化事实和出口差异。状态回填原兼容台账。最小记录含“批次／ID、真实入口、断言、旧与候选修订、结果及证据位置”。合成夹具、真实复演和真机各保留其证据属性。
- **累计候选定稿后跑必需门禁。** 返修先跑目标用例，批末复查完整 diff 再固定候选，一批只换一次内核包。相同修订同一门禁只启动一次。产品选测命中全量时，本地不补跑，以推送后的 CI 为准；内核仍按仓规逐项跑 `pnpm run verify`。质量审计和独立安装验收只在 M 包收口时做一次（编排约定的 L3）。M14 用同一候选在旧执行链停用后核完整覆盖，保留真实升级、回退、性能与真机证据。
- **减少重复交接。** 一个执行者领一张有独立行为和写集的单。交接只给该批次 ID、起点、改动文件、目标断言、已有证据和放行条件。台账引用报告，不重贴长日志；缩短上下文及任务消息的同时保留复核所需的 SHA 和实际命令。
