三、模型分工、并发与成本

派单单位是验收分批里的一个子组（如第 2 批的「输入与评分适配」），一单覆盖同一夹具、同一写集下的若干 ID，通常 3–10 个，不按单个 ID 派单。由同一 SOL 负责这一单的红测、实现、回归和返修。
SOL 的数量有硬上限：同时在办最多 2 个（第二个只在写集互不相交、验收独立、互不等待时开），一个主控会话累计最多派 8 个，不层层再派。SOL 交付并经主控复核后必须立即关闭，不留着备用；同一单的返修交回原 SOL，原 SOL 已关闭就新开一个并只给返修所需上下文。共享契约、迁移序列、数据库写副本或生成产物的工作串行。
新 SOL 只接收当前工单（按 工单/README.md 的派单格式）与必要的文件定位，不复制聊天、不附整份台账或长日志（工具支持时 fork_context=false）。确认 SOL 可写、主控能取回同一份 diff 后再派。SOL 不改台账、不扩范围；主控不与它争写同一文件。不按提交拆单，不逐提交另派审查者。
主控只看回执五行、git diff --stat 和与风险相关的关键文件，不读完整日志。

L1 工单级（每张单）：只跑能区分成败的定向用例，加上该单触及文件的 test:affected 和 e2e:affected。内核工单按仓规跑一次 pnpm run verify。本地不跑产品全量：选测命中强制全量（如改了 pnpm-lock.yaml、packages/contract、迁移或 schema）时不在本地补跑，推送到工单分支，由产品 CI（.github/workflows/ci.yml，全量 lint/typecheck/test/build 加 chromium、webkit e2e）承担全量，主控读 CI 结果。CI 失败只按失败用例定向修。
L2 批级（每批收口一次）：把本批可一起验收的改动固定到同一累计候选，一批只换一次内核包。对完整 diff 先简化、再做一次正确性审查，改后重跑受影响用例，推送后以该候选的一次绿 CI 作为本批全量证据。
L3 包级（每个 M 包收口或发布 PR 转正式评审前一次）：覆盖率、CRAP 复杂度、重复度和变异审计（内核按 ub-mode，产品按产品仓 AGENTS.md，产品仓规没有要求的审计不做），以及干净检出安装验收。L1、L2 不做这些审计，不写合成变异用例。已有变异结果中的待判项，在 L3 统一判读一次，判不了的记为剩余风险，不在工单里补手工变异。
证据复用：同一 SHA 上同一命令的结果直接复用，不重跑；SHA 变了只重跑 diff 触及的用例。正在运行的同一轮直接等结果。临时检出和数据副本：一张工单最多一棵 worktree、一份写副本，放在固定目录（不放 %TEMP%），同一场景续用已有副本；工单关闭时删掉。
