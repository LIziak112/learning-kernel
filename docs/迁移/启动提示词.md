## 工单执行细则

产品仓的 M04 细则见文档修订 `e15378a6` 的 `docs/OwnClass首个练习接入内核任务清单.md`。其中“首个实施动作是 P0”和固定包可行性核验描述首次立项步骤。候选 `f9504ec9` 已锁 K12，恢复时按台账取对应步骤；在候选检出找不到该文档时按上述文档修订读取。

开工预检：分别记录两仓文档提交号、Git 根、实际工作区和分支；文档修订不是产品交付、集成或产物基线。无法核实的交付 SHA 标待确认，不把当前功能分支视作线上版本。确认 SOL 能在指定工作区写入、Astra 能取得同一份 diff；权限或交付方式不通时不派该单。

M00 只冻结分母和证据索引，不做 M14：每个已发现入口要有行为 ID 或有依据的分类，高风险先取代表性旧证据。其余登记“旧侧未测＋负责工作包”，在实施该行为前补证。不得把未测写为兼容。恢复时先核对台账、执行者和实际工作区；同一修订、夹具、环境、命令和断言的可追溯证据可复用，不免除各仓必跑门禁。

先判归属，再写代码：
1. 产品仓只做接入：登录态到可信身份的映射、冻结题目和设置到声明的转换、作业资格与固定路由、兼容旧 API 和页面、教师记录与可重建的读取投影、产品端到端测试。产品契约先改 packages/contract。沿用服务端 packages/grading 的产品判分语义，明确唯一评估执行方，不生成两份正式成绩。
2. 内核公共入口、契约语义、幂等回执、版本冻结、当前授权下的交付、进程恢复和评估去重，只在 learning-kernel 实现。若现有能力够用，内核零提交。若不够，先说明“缺少哪条保证、为何映射不能解决、哪个宿主无关的测试能证明”，在内核仓先红测再修复。不要把 OwnClass 的表、账号或页面带进内核，不要在产品适配器里补一份内核逻辑。
3. 一项需求可以跨仓，一笔提交只能属于一仓。分别建任务分支、分别验证和提交，用同一试点编号关联 PR。需要改内核时，先交付可独立构建、验收的固定产物并记录源码提交号和摘要，再在产品仓锁定依赖。允许本地联调，不得以兄弟目录、浮动分支、复制源码或手改产物交付。若产物尚不可用，保留失败用例并报告，不合入不可独立构建的接线。

按总清单推进：M01 身份与课程，M02 内容/DSL/教学包，M03 讲义与渲染，M04 单选试点，M05 十种题型与练习模式，M06 手写/圈画/保稿，M07 讲练，M08 学生自评，M09 教师评分，M10 记录/订正/错题/重练，M11 学情与导出，M12 AI/MCP，M13 历史与运维，M14 禁用旧执行链终验。每批先跑旧行为，再以相同夹具跑新路径；记录旧实证、内核通过/失败/未测、最小反例、修复归属和两边实测。保留成熟宿主组件，但不允许转调旧引擎伪装成兼容。真实设备手感单独验收，不拿模拟器代替。

仅在 M04 内，按下列 P 项执行：
P0：用一位教师、两名学生、两道合成单选题跑旧链路，记录正常、空答和部分作答、重发、草稿、公布前后与无权读取的真实结果，并查清记录/错题/统计影响。先产出差异表，不先建表。
P1：在隔离库用同一夹具验证固定产物、单步单选和服务端评分。空答不能伪造为有效选项，也不能为迁就内核增加虚假阅读步骤。全新产品检出、没有相邻内核源码也须能构建运行。不兼容时在创建作业前排除，或按双仓约定修复；不静默降级。
P2：创建作业时持久化执行路径，旧数据默认旧路径，身份来自服务端。重试、重启、换账号和关闭开关均不得改变既有实例归属。产品表结构变化用 drizzle-kit 生成迁移。
P3：接通保存、正式交卷和恢复。超时结果未知就保稿，用原操作标识重试。模拟双端争交、内核已确认但产品尚未收到回执、进程重启。跨库不假设同一事务，依据稳定键找回原回执并补投影；不可用时不转旧引擎重交。
P4：用相同夹具分别走新旧隔离路径，通过真实页面核对学生回看和教师记录。检查详情、回执、统计、错题、导出、缓存及已启用的 AI/MCP 出口，分别遵守各自授权；普通学生响应不得带未公布答案或解析。撤权后旧链接和在途读取不得交付旧正文。
P5：先在隔离环境演练故障、备份恢复和关停试点。开关只停止新分配，已交的可读、在做的可续。出现越权、丢稿、重复确认或账实不符就停止新分配。真实班级放量或部署前交接验收证据，取得明确授权。
P6：复盘试点，发现缺口回填总台账。单选通过只完成 M04，不能结束总体任务。暂不适用的功能必须保留后续工作包；若有阻断项，暂停放量而不是删减兼容范围。

纪律与交接：默认用合成数据；只有合成数据不能复现且确有授权时，才从只读一致性快照在服务器侧提取脱敏的最小样本。不要下载整库、凭证、真实作答或附件，不连生产库跑测试，不回灌。行为改动先见到预期红测，再做最小实现。目标测试随小步运行，整批做简化与正确性审查；涉及权限或持久化再核对响应负例与落库事实。产品仓遵守选测、类型和契约生成规则；内核仓运行 pnpm run verify，交付候选做干净检出验收。编码按编排约定派 SOL，不逐提交派单；主控只收完成/阻断摘要并独立复核。不要用放宽门禁换取通过。

每批交接：工单 ID、目标仓及可取得的 diff 或提交号、实际命令与结果、证据位置、未覆盖项及下一步。派单即记在办，回执即记待复核；主控核对落在目标工作区的改动和必要验证后才记通过。仅待 CI、真机或授权的事项注明等待条件，不另派返工，也不算完成。未经另行授权不推送、不合并、不部署。先报告预检和本批首项证据；已授权、依赖满足的工作继续推进，阻断只暂停相关工单。
