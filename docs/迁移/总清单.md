# OwnClass 全量兼容迁移总清单

**完成定义：** 在固定的已交付 OwnClass 基线上，现有用户能做的事，在新学习运行时上仍然能做；已有内容、历史证据、权限、在途作业和未同步稿都有经过验证的保全路径。隔离环境禁用旧学习执行链后仍能安装、运行、升级和恢复，才具备全面切换资格。P0–P6 单选试点只是其中一个批次。任务目前均为规划，引用旧用例不等于新路径已通过。

“全部支持”不等于“全部塞进内核”。保留打磨过的 OwnClass 渲染器、Pencil 交互、评分器、账号和管理界面，只替换它们消费或产出的学习事实。保留宿主组件可以达标；宿主偷偷调用旧提交、旧判定或旧授权引擎不能达标。

本表定义范围、依赖和放行条件，不维护第二套勾选。实际状态、阻断和恢复位置只写[兼容台账](兼容台账.md)。文中产品证据路径相对于 simple-tutor-tool 的已固定版本，不要求两仓相邻。执行前读[编排约定](编排约定.md)。

## M00：冻结分母，再动代码

- 固定实际交付版本、产品集成基线、内核版本（完整 SHA）和差异。当前产品仓检出不一定是交付分支。未发布规划单列，不拿它冒充旧功能；实施期间新发布的功能追加到分母。若文档与实际行为不同，保留复现和差异，请负责人裁决，不以较弱的一方为准。
- 建立逐行为台账，以页面功能清单（产品仓 `docs/页面功能清单.md`）的教师 §2、学生 §3、其他 §4 为起点，反查真实页面/深链、服务路由、契约枚举、DSL 注册表、MCP 工具、存储/迁移、备份清单及测试。记录每个来源的已映射数和未映射项；同一行为跨端合并但保留全部出口。列出无页面的功能、纯宿主保留项，以及明确未发布/已移除项的依据。
- 每个条目记录：ID、旧入口和角色、前置数据/策略、操作和可见结果、拒绝/失败结果、应持久化的事实、旧测试或人工脚本、归属仓、新路径证据、状态、阻断原因。例：讲练首次提交后重发，学生只看到一份冻结作答，讲练进度只增一次；旧题版本请求被拒且原稿不变。不能只登记“支持讲练”。
- 用合成数据在固定旧版本运行，保留公开响应、数据库事实、截图/手动步骤和版本；建立比较时可忽略的随机 ID/时间映射，但不忽略权限字段、历史版本、缺失证据及数量差异。手写原稿按原坐标/底图核对，敏感内容不进日志。未取得旧侧证据的行为保持“待定”，不能写“兼容”。

## 内核质量提升：每一批都要反哺，不预设重写

已读到的三个具体边界：内核构建脚本生成带宿主资源的运行目录；`src/kernel/reading-answers.ts` 对作答数量和单选有效性有约束；`src/kernel/review-access.ts` 读取阅读活动的复盘/评语记录。它们是有效的首版实现，不是通用兼容证明，也不代表必须立刻拆掉。

| 缺口候选 | 先做的对照 | 做到何时才算改善 |
| --- | --- | --- |
| K1 运行入口与练法耦合（M04） | 无 demo 会话、目录和相邻源码，加载同一固定产物接入两个宿主 | 独立检出可运行；产品只导入公共入口，原内核首版验收保持通过。 |
| K2 作答模型与证据（M05–07） | 同一题被两次使用，允许未答交卷的练法与原必答练法分别运行；再用手写替换单选作品 | 原规则不被全局放宽。题型、作品和槽位可按声明区分；重复提交、换版、异常中止仍保留原事实。 |
| K3 评价与授权（M08–12） | 相同冻结作答分别走仅自评、待教师评分、自动后改判；公布前后或中途撤权，从不同出口重读 | 角色、状态、版本及优先级可测试；普通出口无泄露，教师反馈与学生自评不互相冒充。 |
| K4 历史与运维（M13） | 多个历史格式、部分缺附件、未完成尝试；导入中断、恢复、重复运行 | 可定位原始证据、不会重判或重复生成作答；无法无损迁移的条目显式报错并阻止切换。 |

每个候选先记录“旧侧实证 → 内核现状（通过／失败／未测）→ 独立最小反例 → 修复仓和范围 → 两边实测结果”。证据说明只是宿主手感或渲染差距，就复用产品实现，不把 UI 推进内核；内核已有能力就记验证，不造通用层。两仓分别提交，同一 M/K 编号关联；不得在产品仓修一份再复制。

## M13 数据迁移与 M14 最终交付

- 在授权的隔离环境盘点格式与总量：课程/材料/冻结题修订、账号角色、作业及尝试、原答和笔迹、判定与自评历史、订正/错题/导出、附件、在途草稿。给每类指定来源、目标、稳定键、数量/内容摘要、关系和读权限核对办法。留在宿主原存储的数据同样必须能从新链路访问，不以“无需搬表”免验。
- 先用合成的多代数据干跑。旧键到新键可追溯；迁移中断可续、重复执行不增行。核对孤儿、遗漏、重复、附件内容及顺序、逐轮成绩与旧深链。不能把缺件或读失败转成空稿。确需真实形状时按单选清单的数据纪律取授权最小样本。
- 在途卷选择可证明的策略：原引擎排空后迁移，或暂停写入、追平增量并核对后原子切换；未同步客户端先恢复/导出再切。演练切换前后继续作答、故障发生在回执前、回滚后仍读到切换后的新提交。全套恢复包括产品库、内核库、附件、映射和固定产物；备份只有实际恢复成功才算证据。
- M14：在旧执行入口不可用的干净环境，用同一候选产物跑全部兼容条目、历史迁移复跑、关键师生端到端、跨角色防泄露、真机原稿与手感、备份恢复和回滚。性能按旧基线同设备/数据量测量启动、长讲义渲染、大卷保存、笔迹与导出；先约定容许差值，再看结果，不用主观“差不多”替代。主路径人工走“导入→布置→阅读/讲练→作答/保稿→自评/教师判→公布→记录/重练→导出”。
- 发布决策须列：分母及未映射数、通过/失败/未跑、两仓修订与产物摘要、非功能和真机证据、数据对账差异、回退演练结果、负责人确认。**已交付功能未映射、依赖旧执行链、证据缺失、无法无损迁移或无法回退，均不得宣称全量兼容。** 停止扩面不等于放弃该项。实际生产切换和旧链删除另需授权，不以文档、演示截图或试点通过代替。

## 执行节奏与必读入口

先完成 M00；M04 可借用 M01/M02 的最小夹具，不必等整个管理端迁完。表中依赖限制放行，不要求跨多个域一次交 PR；例如 M05 的单一题型通过后可启动对应自评对照，但 M08 完成仍需覆盖全部适用组合。每次交接只报当前行为 ID、归属仓、实际命令/修订/结果、差异和下一条。按根规则走选测和 PR 全量；不能用单选试点的排除条件删减最终验收分母。
