# 学习内核工程接入说明

版本：v1.0 · 2026-11-19

本文面向宿主开发者、扩展开发者和实施 Agent，说明如何把新能力接入统一内核。领域规则以[学习平台内核参考架构](学习平台内核参考架构.md)为准；迁移步骤和验收记录见[迁移与验收清单](迁移与验收清单.md)。

## 1. 从现有项目接入

[宿主接入文档](../README.md#接入外部宿主)给出构建、打包和严格类型宿主的调用样例。[服务端包入口](../src/server.ts)是宿主 API；[选择题评估器](../src/contracts/choice-evaluation.ts)是当前已使用的版本化 SPI。已发布 JSON 由[练法契约](../src/contracts/reading-publication.ts)解析。本文其余伪代码描述设计。

两步阅读通过 [HTTP 宿主](../src/host/server.ts)进入同一运行时。[演示](../README.md#浏览器演示)从学生选据到教师复核，使用本地 SQLite 和锁定的 Chromium。OwnClass 的产品契约与内容 DSL 留在产品仓；其公布字段和旧协议的可见结果由宿主仓核对。

K14 的固定包新增单步逐题原值声明 `response-group@1`。宿主以 `saveResponseDraft` 保存布尔或原字符串，以 `confirmResponses` 固定原答和回执，再用 `recoverResponseConfirmation` 按当前授权取得确定判定或 `needsReview`。评分键逐题为布尔，原字符串及空格逐字保留，空字符串与缺答分别编码。发布、升级和受限字段进入固定版本的回归。包摘要及使用范围由宿主仓记录。

K15 在单步整卷单选发布时支持 `materials`。每个材料输入声明唯一使用位置及 `{ id, version }`，指向同一发布中的不可变材料定义。`read` 只在当前步骤对应的 `inputs` 中还原精确材料。更换一份材料时发布新练法版本，已打开活动保留原引用。旧单材料声明和宿主附加附件继续沿现有入口。

K16 的单步原值整卷增加 `optionIndexArray`。宿主用 `saveIndexResponseDraft` 和 `confirmIndexResponses` 保存并确认有序索引数组，以 `recoverIndexResponseConfirmation` 按当前权限取回原值和判定。私有 `acceptedIndexes` 固定实际正确集合，`indexResponseEvaluators` 接收该集合和原值。显式空数组与无草稿分别存储；旧标量类型沿原接口。

K17 通过 `question-delivery@1` 在同组冻结题声明不同作答形态。整卷命令以 `source: "whole"` 确认一份回执。逐题活动声明每题唯一的交付位置，以 `source: "question"` 确认一题，以 `source: "finish"` 固定尚未确认的剩余题。宿主共用 `saveQuestionDeliveryDraft`、`confirmQuestionDelivery` 与 `recoverQuestionDelivery`，并按当前访问资格恢复指定操作的原回执与评估。逐题主动空交和提前收尾的被动未作答由确认来源区分。现有应用按各自冻结的旧槽继续读写。

宿主把冻结活动和每次确认的操作意图先写入自己的持久存储。恢复后按回执幂等投影，逐题活动仍在途时也可恢复。配对备份可从声明包含 `receipt` 的 `read` 视图取得全部 `questionDeliveries`，将每个实际位置和回执与宿主按操作恢复的结果双向核对。学生入口只使用产品获准字段，冻结评分键和确认恢复明细留在可信宿主。

K18 允许同一交付组声明 `orderedTextBlanks`。题面冻结 `blankCount`，私有 `acceptedBlanks` 按相同空位次序提供候选文本。`orderedTextEvaluators` 接到按原序保存的 `string[]` 或缺稿 `null`，沿原任务返回已判或待评。空数组和全空数组保留各自草稿修订，均不登记表现。实际值可短于或长于空位数，完整度及待评的教师或学生处理关系由宿主的冻结规则决定。

## 2. 先判断这次变化属于哪一层

| 需求 | 优先修改的位置 | 不应直接修改什么 |
|---|---|---|
| 新题目、新材料、已有能力的新组合 | 内容、模板与布置 | 核心提交和授权逻辑 |
| 改布局、自由跳题、编辑体验 | 宿主与工具界面 | 权威步骤状态、正式提交事实 |
| 新输入方式、新作品格式 | 工具与作品类型接口 | 内核里的题型专属分支 |
| 新评分方法、外部评价服务 | 评估器及其任务适配 | 学生原答、当前成绩字段 |
| 新反馈时机或粒度 | 已批准的具名教学策略 | 平台身份、资源和撤权检查 |
| 新复习算法或分析指标 | 调度、查询或派生计算接口 | 历史提交和既有判定 |

UI 布局槽位由宿主负责；活动的证据槽位仍由内核解释。文章段落、材料版本、证据范围也保留稳定引用。内核不决定左右分栏，但要知道本次交付属于哪个活动、哪次尝试、哪个提交位置。

默认工具和默认评估器必须使用公开接口，不得借“内置”身份直接写业务表。数据库、时钟、文件存储等通过明确端口注入；身份核验、事务、幂等和授权底线不向普通扩展开放替换权。

## 3. Kernel API：宿主怎样调用

API 是应用使用内核的入口。传输方式可沿用现有 HTTP、进程内调用或其他协议，行为语义保持一致。

| 操作类别 | 请求必须明确的内容 | 返回与行为 |
|---|---|---|
| 启动活动 | 操作标识、定义版本、布置或自练来源、受托关系（如有） | 固定本次依赖和规则，返回实例、当前尝试及获准材料；启动重发返回同一实例 |
| 读取恢复状态 | 实例、读取用途 | 返回当前尝试、已确认交付、待评状态及获准反馈；不产生新的学习事实 |
| 保存草稿或作品 | 所有者上下文、类型、版本条件、内容或已保存文件引用 | 保存个人内容；不自动确认步骤或计分 |
| 正式提交 | 操作标识、实例、尝试、提交位置、固定的值或作品引用、并发条件 | 同事务确认交付、推进权威状态并登记必要待评工作 |
| 请求重做 | 目标步骤或活动、所见状态、操作标识 | 核验资格后创建新尝试或新实例，不覆盖旧交付 |
| 读取交付与反馈 | 提交身份、用途、字段与分组请求 | 每次按当前权限与反馈策略生成结果，不返回未经裁决的原始数据库对象 |

实际操作者、所属账号和有效委托必须由服务端认证上下文确定，不能接受客户端自报的角色作为授权依据。学习者与实际发起者需要分别记录。

### 最小交互示例

以下为接近 TypeScript 的调用示意。`api`、`recovery`、`delivery` 等名称不指向已发布库。`delivery` 是已固定的作答值，或已经可靠保存的作品版本引用。

```ts
const state = await api.readActivity({ runId });

// 先记录待确认命令。超时后恢复这份命令，而不是重新读取当前草稿。
const command = {
  operationId: recovery.obtainOperationId(),
  runId,
  attemptId: state.currentAttemptId,
  submissionPoint: "answer",
  expectedRevision: state.attemptRevision,
  delivery,
};
await recovery.remember(command);

const receipt = await api.submit(command);
await recovery.markConfirmed(command.operationId, receipt.submissionId);
```

相同操作、相同内容重发返回同一业务结果；相同操作改用其他内容应返回冲突。已确认操作的回执身份稳定，可见反馈仍按读取当时的权限生成。对“已经确认过的原操作”应识别其既有结果，不能仅因尝试修订号或截止状态后来变化而把重发当成新提交拒绝。

两个窗口使用不同操作标识争抢同一交付位置时，还要遵守提交模式的业务唯一性和并发约束。幂等键不能替代这些约束。宿主在冲突时保留本地输入，读取当前状态并向用户解释结果，不静默覆盖已确认交付。

## 4. Plugin SPI：扩展怎样提供能力

SPI 是扩展实现需要遵守的接口。注册表负责按身份、版本和能力发现实现，不应成为可以任意读取全局服务的入口。

| 能力类别 | 输入与输出责任 | 约束 |
|---|---|---|
| 工具 | 接收获准材料、草稿和能力上下文；产出作答值或作品 | 负责挂载、恢复、卸载与资源释放；不直接确认活动状态 |
| 作品类型适配器 | 校验内容格式，按能力验证源片段或生成受支持的表示 | 声明自己验证了什么；不把来源声明冒充已核验关系 |
| 评估器 | 接收固定交付、获准评估依据；产出候选判定和依据 | 不自行覆盖有效成绩；外部调用受任务与出站授权约束 |
| 教学策略 | 根据获准上下文决定反馈时机、字段、粒度与追溯要求 | 不能扩大主体、模板或布置授予的范围 |
| 流程决策实现 | 接收已记录状态和明确输入；返回允许的转移或任务意图 | 决策与副作用分开，不自行写库或隐式获取可变外部事实 |
| 调度与派生计算 | 消费有版本、可追溯的事实；返回建议或计算结果 | 重建结果不重放真实业务动作；发起活动仍走授权命令 |

不是每一种能力首版都需要独立抽象。先为实际切片使用的类别定义窄接口；遇到跨练法共同规则时再扩展，说明旧实例行为并增加对应验收。

### 评估器 SPI 示意

以下仅展示角色边界，`EvaluationInput` 等类型应在现有公共契约中具体化。

```ts
interface Evaluator<I, R> {
  id: string;
  version: string;
  evaluate(input: I, context: EvaluationContext): Promise<R>;
}

interface EvaluationContext {
  taskId: string;
  evaluationRunId: string;
  signal: AbortSignal;
  // 仅注入本次任务获准使用的服务；不提供任意数据库连接。
}

// 注册候选实现，不意味着该实现自动获得读取答案键或出站权限。
registry.registerEvaluator(choiceEvaluator);
```

评估输入应包含提交、评价单位、目标、规则版本和本次评估身份。返回结果包含候选判定与依据，不携带可以直接改写活动表的闭包。人工判定和自动结果均进入统一裁决路径。旧任务晚于新复评返回时，按授权顺序和判定规则裁决，不能仅按到达时间选最新结果。

具名、纯决策函数适合流程条件；评估器本身可以执行获准计算或外部调用，不必伪装成纯函数。但重试、超时和结果写入必须有明确协议。

## 5. 扩展声明与发布

一个扩展至少说明身份、发布版本、兼容的公共 API 版本、输入输出类型、必需能力、恢复或只读方式，以及实际使用的服务。依赖范围用于选择兼容版本；发布后的执行定义记录解析出的具体版本，不能在恢复时重新选择“最新”。

公开题面、受限评估依据和最终用户结果应分成不同的数据载荷。公共前端包和类型导出不得意外打包答案键、评阅秘密或服务端凭据。

发布校验至少检查类型、引用、所需能力、声明范围内的流程可达性和权限冲突。错误返回稳定类别、字段或步骤位置、原因与修复方向。错误名称例如 `CAPABILITY_MISMATCH`、`REVISION_CONFLICT` 仅为建议，应与仓库约定统一。

首版执行定义支持步骤、依赖、工具与槽位、完成条件、重试和新尝试即可。静态材料条件可在发布时展开；截止、评估完成、教师开放等依旧是运行时条件。YAML 与代码构建器共用同一语义，不要求把任意代码自动转换为流程图。无法支持的表达明确报错，不放入无约束的通用 `context` 来绕过校验。

## 6. 接入作品的两条路径

| 路径 | 使用方式 | 槽位需要声明什么 |
|---|---|---|
| 经验证的源片段 | 由平台支持的可信实现核验源版本、选择范围和访问资格 | 是否要求核验来源、允许哪些类型和上下文 |
| 独立冻结交付物 | 工具在客户端导出可独立保存的成果，登记作品版本后提交 | 是否接受独立成果，以及本次评阅依据的格式 |

独立交付物的最小顺序是：生成固定内容与预览，上传并确认持久化，登记版本，再以统一命令确认提交。上传成功而提交失败的对象可以等待清理；提交成功却缺附件的状态不可接受。回执超时重试沿用原操作及原交付物，不重新导出当前草稿。客户端点击时间不自动等于服务端确认时间。

`sourceRef` 可以记录来源，但服务端必须区分客户端声明、已核验和不可核验。客户端不得自行宣称已验证。来源引用不授予原草稿访问权；新文件 ID 也不自动增加独立表现次数。

权威原始内容与只读表示须注明各自用途、对应修订和生成方式。评阅者只取得明确选择的交付内容及获准上下文。未知私有格式不能默认随预览下发；一张裁剪图不能证明附带 JSON 或工程包只含该片段。低门槛路径可以直接以平台支持的独立图片、文本或音频作为本次评阅依据。要求核验源范围的槽位不能静默降级为图片上传。

## 7. 查询、教学策略与任务执行

身份、委托、资源归属、参与资格、评阅关系和当前撤权由平台统一核验。教学策略只决定获准范围内的反馈方式。首版采用少量可信、具名、有版本的策略；作者选择策略及受约束参数，不编写任意权限程序。

查询先限定可访问资源、字段、分组、子集和追溯范围，再形成结果。按篇盲批不得通过任意子集、标签筛选或下钻泄露逐题结果。缓存命中、历史回执、导出和 Agent 查询也经过同一裁决入口；不得把完整敏感快照交给任意扩展，再依赖它自行隐藏字段。

提交确认、权威进度和必要任务同事务落库。任务使用明确身份、领取与超时回收、重试及最终失败状态；重复执行可以发生，业务结果须去重。评估失败不删除已经确认的学生提交。简单查询可直接从有效判定计算，复杂预计算按需要增加，结果注明范围和截至时间。

## 8. 怎样证明接入完成

OwnClass 从宿主仓记录的恢复点选择实际入口，以冻结的产品行为和失败用例判断是否需要扩展公共契约。现有两步阅读及两次作答样例列入内核回归；常规阅读评估器接口的统一要有具体产品缺口才派单。英语 demo 的双轮练法与存量导入留待该项目启动。每次接入报告新增声明、扩展文件、核心改动和原因。

宿主必须能恢复当前尝试、已确认交付与待评状态；新增扩展不得依赖内部业务表；旧实例在发布新版后仍按固定版本解释；权限收回后所有读取入口遵守新范围。具体故障场景和验收证据记录在[迁移与验收清单](迁移与验收清单.md)。

新作者首先需要一个可运行的最小例子、明确错误和预演入口。“十分钟上手”是待实测的体验目标，应由未参与内核设计的人或独立 Agent 完成指定任务来验证。参考项目的适用范围见[架构决策与参考资料](架构决策与参考资料.md)，按问题提取机制，不把整套上游框架同时引入。
