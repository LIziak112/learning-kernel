# 在线两步阅读实施规格

在线两步阅读是个人开发首版中第一个使用内核的练法。本规格用它验收提交、恢复、评阅和读取。实现范围以[个人开发首版的交付范围](学习平台内核参考架构.md#个人开发首版的交付范围)为准，题面、模板、判分键和普通成功路径见[两步阅读练法](学习平台内核参考架构.md#两步阅读练法)。

内核通过同一组入口启动实例、确认指定步骤尝试的提交、恢复进度和按权限读取结果。`evidence`、`decide`、两个引文角色、三题、八分钟、人工优先及整篇公布都由这份模板或布置指定。选区工具产出带角色的原文范围，服务端按槽位约束校验，选择题评估器核对答案键。宿主负责选段、题卡和操作回执的呈现。

本规格按单服务、单 SQLite 库实施。评估可以由同一进程读取持久化待评记录并执行。下文的“投递”包含这种方式，重启指服务进程重新启动。两端是同一账号的两个在线会话。

## 验收起点

每个场景从独立数据开始，以同一名学生、布置 `assignment-1` 和实例 `run-1` 演练。服务端固定 `reading-library@1`、`library-hours@1` 和 `library-key@1`。时钟可控，首次启动后的第八分钟为截止时刻。

- **已交选区。** 第一步已确认 `sub-1`，其 `quotes` 槽位包含作品 `selection-1@1` 的两处引文，观察取 `p2`，条件取 `p3`。两段合计一个选据表现 `cite-1`。即使学生另存第 2 版，第二步仍读取第一步确认的片段。
- **交卷输入。** 两个窗口属于同一学生、同一实例、同一次 `decide` 步骤尝试。窗口甲提交 `q1=A、q2=B、q3=A`，窗口乙提交 `q1=B、q2=A、q3=B`。两端都引用 `sub-1.quotes`。按初始键，甲的整篇结果为 **1/3**，乙为 **2/3**。后文称获准写入的正式作答为 `sub-2`。
- **初始权限。** 学生有参与资格，复盘关闭。负责布置的教师兼任获准评阅者。选据反馈可选，整篇分母始终为三题。批准整项重练会产生新实例。

## 写入、评估与读取契约

| 操作 | 入参与判定时点 | 成功结果与持久化边界 |
|---|---|---|
| 提交整篇 | 定位实例、步骤尝试和正式作答用途，传操作标识、选区引用和三题选择。服务端按槽位契约核对引用、题目集合及合法选项，在写事务中核验当前权限、引用版本、截止和封存状态。 | 本练法每次尝试只收一次正式作答。以实例、步骤尝试和用途定位唯一交付位置，在同一事务中封存，并保存原答、选区引用、三题的新表现标识、操作回执，以及本模板触发的步骤完成、实例完成和待评任务。引用的片段须已可靠保存。事务成功后才返回确认。 |
| 执行待评任务 | 任务持久化后允许重复投递。以正式提交和固定评估规则标识这次自动评估，每题另以题号标识该次评估的结果。重启后重新领取待处理或领取已失效的任务。 | 保存各题自动结果，三题齐备后将任务标为完成。重复执行复用已有结果，迟到的自动回报保留其来源。当前判定始终按评价策略选取。 |
| 改判或撤销 | 使用模板授予的 `reviseQuestionVerdict` 权限。请求带操作标识、提交、题号、目标、所见修订号和理由。改判附新判断，撤销附目标人工判定标识。 | 在同一事务校验修订号、追加评阅事件并更新该题的当前判定与修订号。整篇计数读取同一组有效判定。本规格允许直接按三题读取时计算。 |
| 读取或重取回执 | 服务端按当前身份、实例、用途及公布范围裁决。原操作回执记录已确认的事实，成绩与可读字段由本次读取时的权限和有效判定产生。 | 学生交卷后可见本人原答及整篇待评状态。三题判定齐备才提供整篇计数。复盘当前开放且满足整篇公布条件时，才提供逐题判定和写给本人的选据反馈。 |

有权调用时，先处理同一主体、实例和操作范围内已确认的操作标识。原请求重发返回同一回执，相同标识更换作答、版本或撤销目标返回 `409 OPERATION_CONFLICT`。对新的交卷请求，位置已封存返回 `409 ALREADY_SUBMITTED`，未封存但服务端裁决时已到截止时刻返回 `409 DEADLINE_PASSED`。合法新写入与截止、撤权按服务端生效顺序裁决。以下错误和冲突均不新增提交、表现或评阅事件。

## 场景一　双端同时交卷

**操作。** 在截止前让甲、乙同时提交，各用不同的操作标识。第一轮控制甲先完成写事务，第二轮重置数据并交换顺序。另做一次对照，让两个不同操作标识携带相同答案。

| 事务顺序 | 两个窗口的结果 | 教师与系统记录 |
|---|---|---|
| 甲先、乙后 | 甲获 `sub-2`。乙获 `409 ALREADY_SUBMITTED`，保留本机草稿，刷新后看到甲实际交出的原答。完成评估后两端均见 **1/3**。 | 教师看到甲的三项选择。一份正式作答、一个初始评估任务。 |
| 乙先、甲后 | 乙获 `sub-2`，甲获同一冲突。两端刷新后看到乙的原答，评估后均见 **2/3**。 | 教师看到乙的选择，三项选择全部来自乙。 |
| 相同答案、不同操作标识 | 先确认者成功，另一请求仍获封存冲突。若成功方因回执丢失以**原操作标识和原内容**重发，则取回原确认。 | 相同答案不会把两个独立请求认作一次重发。三轮各自都只有两次提交（含第一步）、一次选据表现、三个选择题表现和一次活动完成。 |

**截止边界。** 让甲在截止前确认、截止后重取回执，应能按当前权限取回 `sub-2`。重新从仅有 `sub-1` 的状态开始，让两份新请求都在截止时刻或其后接受服务端裁决，均应得到 `DEADLINE_PASSED`。第一步及个人草稿保留，正式作答、待评任务和整篇分数均为空。

若甲已成功，再沿用甲的操作标识、把其中一题改成另一合法选项，预期为 `409 OPERATION_CONFLICT`。教师读取的仍是甲首次确认的三项选择。

## 场景二　交卷后重启

**操作。** 采用甲的答案，暂停评估，在交卷事务前后及评估过程中分别终止服务。每次重启只使用持久化数据恢复。

| 故障位置 | 恢复后应观察到的结果 |
|---|---|
| 交卷事务尚未提交 | 只存在 `sub-1`。无正式作答、完成事实、成功回执或待评任务。原操作可在截止前重试成功，若重试时已到截止则保稿并返回截止错误。 |
| 事务已提交，回执尚未送达，或任务尚未投递 | 学生重新进入即见本人原答、已交卷和整篇待评。教师可见一份正式作答。原操作在截止后重发仍返回 `sub-2`。重启后的服务能找到待评任务，无需学生再次交卷。 |
| 第一题结果已落盘，或三题均已落盘但任务尚未确认完成 | 重新投递同一任务。已有题级结果各保留一份，补齐缺项后收尾。部分结果期间学生只见整篇待评，三题齐备后见 **1/3**。教师可按权限核对三条自动判定。 |

**最终计数。** 对已确认的交卷再重启一次并重复投递，仍应有两次提交、一次选据表现、三个选择题表现、一个已完成的初始评估任务、三条初始自动判定。八分钟从原实例启动起算。

## 场景三　同题连续改判

采用甲的作答并完成初始评估。目标固定为 `sub-2 / q2 / interpret`，下表的修订号仅属于这个目标。初始自动判定在本场景中保留为有效候选。布置处于盲批阶段。第二次人工改判刻意模拟一次误操作，以验证撤销后的回落顺序。

| 操作 | 写入结果 | 第二题的当前依据 | 学生整篇结果 |
|---|---|---|---|
| 初始状态 | 修订 0 | 原自动判错 | 1/3 |
| 教师甲窗口基于 0 提交 `review-1`，判对 | 成功，修订 1 | 人工判定 1，对 | 2/3 |
| 同一教师乙窗口仍基于 0 提交另一改判 | `409 VERDICT_CONFLICT`，仍为 1 | 人工判定 1，对 | 2/3 |
| 乙读取 1 后以新操作 `review-2` 改判为错 | 成功，修订 2 | 人工判定 2，错 | 1/3 |
| 基于 2 试图撤销已被后续改判替代的判定 1 | `409 VERDICT_CONFLICT`，仍为 2 | 人工判定 2，错 | 1/3 |
| 基于 2 撤销当前人工判定 2 | 成功，修订 3 | 回落到人工判定 1，对 | 2/3 |
| 基于 3 撤销当前人工判定 1 | 成功，修订 4 | 回落到原自动判错 | 1/3 |

教师可追溯原自动判定、两次改判和两次撤销，另外两题的判定与修订号保持原值。学生只获整篇计数。处于修订 4 时重发原 `review-1`，应返回已确认的原操作回执，当前修订仍为 4。另用新操作标识基于 0 写入也应报版本冲突，即使修订 0 和 4 的判定恰好相同。以上操作均不增加提交和原始表现。若另设用例使所有候选都失效，该题回到待评，学生仅见整篇待评。[连续改判与撤销](学习平台内核参考架构.md#连续改判与撤销)

## 场景四　撤权后重新读取

**起点。** 甲已交卷，教师已把第二题改为正确，整篇为 **2/3**。先开放复盘，让学生读取一次逐题结果、评阅者读取一次已交引文，并保留相应的缓存标识和读取链接。下列三项从这个起点分别执行。撤权生效后再发起读取，另让一项在途读取停在交付前，待撤权生效后继续。

| 收回什么权限 | 再读时允许什么 | 必须观察到的限制 |
|---|---|---|
| 布置教师只关闭复盘 | 学生仍可读自己的原答、已交引文和整篇 **2/3**。获准的评阅者仍可正常评阅。 | 逐题复盘专用读取返回 `403 FORBIDDEN`。普通详情、统计及导出按盲批范围返回，均不含逐题判定、题号对应的对错或选据评语。 |
| 收回评阅者对该实例的授权，且其没有其他读取依据 | 学生继续使用自己的授权。个人作品及已交证据的版本仍保留。 | 原评阅者重读提交、片段、评阅历史、导出或重发原改判操作，均返回 `403 FORBIDDEN`。旧片段链接、预览和缓存也须经过当前授权。 |
| 收回该学生对活动的参与及记录读取权限 | 学生在个人工作区仍可按作品所有者权限保留自有稿。其余仍有权的角色按各自授权读取。 | 从旧链接重进、查询整篇指标、导出或重发原交卷操作，均返回 `403 FORBIDDEN`。响应不带旧回执、提交标识、受限题面、选区或成绩。 |

**交付时点。** 对已命中缓存、旧链接和交付前被暂停的请求，服务端在交付时执行当前授权。受限内容不能通过复用旧正文或返回指示客户端复用旧表示的 `304` 再次交付。在线宿主获知收权后移除对应视图与受限缓存。此前合法展示的事实留在受权限控制的历史记录中，接收者此前已取得的副本可能仍由其持有。本练法关闭外部 AI 出站，以上权限变化均不触发对外发送。

## 验收取证

用两个独立会话和可控服务端时钟执行上述步骤，在指定写入、评估和交付时点暂停请求，重启场景则终止并重新启动服务进程。每轮同时核对客户端实际收到的响应、教师读取的历史，以及持久化的提交、原始表现、题级判定、活动完成和评估任务数量。记录操作标识与修订号即可串起同一轮证据。判分键只进入服务端夹具。

### 用不同声明检验内核边界

下列对照共用同一版内核和内置组件。只替换声明、材料或评分配置，每份声明都从相同的启动、提交、恢复与读取入口运行，并保留原版实例供核对。若必须给内核增加按练法名称、固定步骤名、题号或 demo 阶段名分派的业务分支，该项验收失败。

| 替换内容 | 可观察结果 |
|---|---|
| 给练法、步骤和槽位换用新标识，更新所有引用；题目集合只取原前两题，配套判分键保留原两项。 | 两端仍只能确认一份正式作答。用甲的前两项选择交卷，评估后为 **1/2**，把第二题改判为对后为 **2/2**，撤销后回到 **1/2**。此时恢复一份已按原键判分、未经改判的原版交卷，仍为 **1/3**。 |
| 同一材料仅保留选据步骤，以该次提交确认为结束条件，省去选择题、评估器和分数公布。 | 提交合规选区即完成，重启后能取回同一回执和获准片段。系统记录一次提交、一次选据表现，自动评估任务为零，学生看不到分数或待评提示。 |
| 从颉斌斌英语阅读 demo 取“两次作答分别保留”这一点做小型对照。给同一道题声明两个依次开放的作答步骤，沿用单选工具，第二步将首答作为只读输入。模板以第二次提交结束，省去选据、限时、评估和复盘页。 | 第一次交 A，重启后仍能读到 A 并进入第二个作答步骤。第二次交 B 后活动完成，两份回执各自指向 A 和 B。再恢复仍可读到两份原答，评估任务为零。完整 demo 的预判、分轮揭晓与复盘另由其练法及宿主定义。[demo 的分层](学习平台内核参考架构.md#颉斌斌英语阅读学习方法-demo-的分层) |
