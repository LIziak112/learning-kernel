# 学习平台内核首版实施清单

**交付目标**　在本仓从空数据库启动一个在线学习宿主。学生可以交证据、交答案、退出并恢复，教师可以评阅和控制公布范围。更换练法声明后，同一套内核可以完成单步或多步活动。执行到 T10 并通过终验，就可以交付这个版本。

**产品依据**　职责及首版范围见[学习平台内核参考架构](学习平台内核参考架构.md#个人开发首版的交付范围)。练法的输入、四个异常场景和三个对照变体以[在线两步阅读实施规格](在线两步阅读实施规格.md)为准。最初两份依据来自 simple-tutor-tool 的参考架构修订 `64b3b88d`，实施清单引入时的修订为 `6d23f4e2`。本仓 docs 目录维护当前规范，题面、评分夹具和验收用例按此落实。

## 在本仓中怎样看见这套架构

参考架构第 0 章区分**内核、练法与布置、工具与评估器、宿主应用**四方职责。以一次交选区为例，练法给出目标、材料引用、工具和证据槽位。宿主显示原文，让学生选择。选区工具把选择表达为带材料版本和使用位置的片段，内核核验声明与权限，在 SQLite 事务中确认提交并推进步骤。刷新后，宿主从内核读取已授权的原提交。

本仓可按下表组织代码。路径是建议，执行 Agent 随任务建立实际用到的模块。四方共用的输入、输出和能力描述在契约目录定义一次。

| 责任方 | 建议落点 | 首版边界 |
|---|---|---|
| 内核 | `src/kernel/`，共享契约在 `src/contracts/` | 处理发布校验、资源与目标引用、实例和步骤尝试、作品与提交、有效判定及授权读取。按已登记的能力调用工具或评估器。 |
| 练法与布置 | `practices/` | 声明目标、步骤、槽位、放行、观察单位、计分和公布策略。受限判分材料仅由服务端载入。 |
| 工具与评估器 | `src/builtins/` | 选区工具、单选工具和服务端评分器各自声明输入输出及版本。工具输出由内核校验并确认。 |
| 宿主应用 | `src/host/` | 组装服务和内置能力，提供身份会话、HTTP 入口及浏览器界面。题卡、工作区和复盘页消费服务端授予的字段。 |

## 给执行 Agent 的工作约定

- 在本仓使用一条主线。参考架构、在线两步阅读规格和本清单同放在 docs 目录。旧项目供开发时参考，构建和运行所需的代码、声明、材料、锁文件和测试夹具都在本仓维护。历史数据迁移、完整英语 demo、离线同步与第三方插件留到首版之后。
- 采用 TypeScript strict、Zod、单服务进程、一个新的 SQLite 文件和少量内置工具。在目标机器固定可安装的 Node、pnpm 和 SQLite 驱动版本，按任务逐步增加文件和表。
- 练法先用能经 Zod 校验的 JSON 声明。参考架构里的 YAML 是作者预演示例。服务端保存唯一的受限评分键，前端只取获准投影。时间、身份和权限由服务端提供。测试可设时钟和故障暂停点，这些控制只接到测试进程。
- 每次取第一项未完成任务。在行为改动前先运行一个会因目标行为缺失而失败的用例，补契约和实现后运行该用例，再运行累计验收 `pnpm run verify`。从 T01 起，这条命令必须实际运行类型检查和已交付的测试，报告用例数，对失败、零用例或缺少已交付验收组返回非零。测试数据库和演示数据库使用不同路径。
- T 编号是里程碑，不是提交单位。一个 PR 交付一个可独立验收的行为，可含多个带测试的小提交；每步跑目标测试，整批审查，不逐提交发起大审查。只有该 T 的所有批次和原完成条件都通过累计验收，才在收尾提交勾选。交接写任务号、关键红测、实跑命令与结果、提交号（如有）及下一步；失败时保留未勾选状态和复现输入。

### 批次与停点

只细化眼前已授权的一批。下表划分审查边界，不替换后面的验证条目，也不要求机械凑够提交数。

**定点参考。** 首次作出或重新审视关键建模决定时，先写清要回答的问题，再从[开源实现阅读索引](学习平台内核参考架构.md#开源实现阅读索引)选与之相关的具体实现对照。把结论和本仓验证用例写在作出决定的 PR 里；后续沿用该决定就复用记录和测试，不逐提交重读。来源不可访问时如实说明，不把链接当作读过的证据。

T01 的文件库迁移直接按本仓规格验证，不要求阅读外部项目。T04 首次决定同一材料如何在两个步骤中引用时，对照索引中的 XBlock `Scope`：哪些信息随材料共享，哪些属于使用位置？用本仓用例证明两步引用同一材料版本、位置各自独立，且第二步看到的引文仍指向第一处。需要验证的是本仓行为，不是复刻 XBlock 的类型结构。

| 里程碑 | 建议节奏与批次证据 |
| --- | --- |
| T01 | 复用已有工具链、锁文件和 `verify`，一批交付文件库的首次迁移、重复初始化和关闭重开；不重复搭架子。 |
| T02 | 同一 PR 内依次验证启动重发、提交重发、升版后仍读原证据及无权账号读不到。用同一单步夹具替换步骤和槽位标识再跑一次，提前发现写死的名称；不提前建设通用框架，不替代 T09。 |
| T03 | 一个浏览器闭环，不按组件拆 PR。到此安排第一次负责人亲手选段、提交、刷新回看的体验；自动化通过与人工体验分别记录，不把未体验写成已验收。 |
| T04 | 三批：① 从发布入口接受有效声明、拒绝错误引用与绑定；② 选据提交后放行第二步，刷新仍能定位原位置和版本；③ 交卷与待评同事务落盘，初判 1/3，盲批学生拿不到评分键。三批齐备再验收整条网页流程。 |
| T05、T06 | 双端争交、进程中止恢复各自一批。每批同时核对调用方收到什么及数据库留下什么。重复的会话、暂停点和事实核对先提取测试夹具；确有反复选错入口的问题才增补技能。 |
| T07 | 同批小步推进改判留史、撤销与冲突、迟到结果不覆盖人工判定；最后连跑完整分数序列。 |
| T08 | 两批：① 按角色及公布条件核对页面、详情和导出的实际字段；② 撤权后复查旧链接、条件请求、在途交付与原操作重放。分批的是验收，不是授权：每个入口首次交付即检查权限。 |
| T09、T10 | T09 的三个对照可分提交，但须由同一构建产物整批验收；T10 独立从干净检出复验，不夹带新功能。 |

## 按顺序实施

### T01　让空仓库可以独立验收

- **前置**　从本仓检出源码，确认 docs 目录的三份设计文档齐备。
- **交付**　建立最小工程、依赖锁文件、SQLite 建库入口、第一项数据库迁移和 `pnpm run verify`。把运行环境和安装命令记入 README。用例使用临时文件库。
- **验证**　先让“再开同一个库仍读得到迁移版本”的测试失败。实现后在同一路径连续初始化两次，核对迁移只生效一次。关闭、重开，版本仍在。确认故意让断言失败时验收命令返回非零，恢复断言后通过。
- [x] **完成条件**　全新检出可按 README 安装，至少一个真实数据库测试通过。下一项可以直接开始写学生操作。
- **验收记录**　独立检出 `562762b`，使用 Node 24.19.0 和 pnpm 12.6.0 运行 `pnpm install --frozen-lockfile`、`pnpm run hooks:install`、`pnpm run verify`，11 项全部通过。文件库目标用例 2 项，红测因缺少迁移表返回 1，故意改错数据库断言后累计验收也返回 1。恢复后通过。下一项为 T02。

### T02　完成第一笔单步证据提交

- **前置**　T01 通过。
- **交付**　一份只收一段引文的最小练法。给材料登记标识、版本和来源，选区记录它引用的材料版本、使用位置及范围。先定启动、保存作品版本、提交和读取的输入输出，再连接服务入口与 SQLite。已登录学生从服务端会话取得身份。提交事务固定作品版本和片段、生成回执、登记一次原始表现，并按声明完成活动。首版操作标识由调用方生成，重试同一动作时沿用。
- **验证**　用真实服务启动活动、保存作品第 1 版、提交。模拟已确认但回执丢失，用原操作及相同内容重发，应取回同一回执。作品另存第 2 版后重开同一数据库，读取已交证据仍是第 1 版的片段。换一个无权账号读取该提交，应遭拒绝。
- [x] **完成条件**　库中恰有一份提交、一次原始表现、一次完成，确认结果未安排评估。T04 建立待评记录后，用本用例补查待评任务为零。用同一启动操作重发得到原实例。能从服务入口复现整个过程。
- **验收记录**　“登录学生通过 HTTP 启动单步练法并收到带步骤尝试的回执”先因入口返回 404 失败。目标测试 `node --test tests/database.test.ts tests/single-quote.test.ts` 通过 10 项，`pnpm run verify` 通过 20 项。两套步骤和槽位标识各确认一次提交和表现，事务冲突用例核对三类事实均回滚。下一项为 T03。
- **定点参考**　对照 Moodle 的 `mod/quiz:attempt` 和 `mod/quiz:reviewmyattempts` 区分写操作与本人回看，本仓对每次读取重新按会话核验归属。对照 `xmldb_quiz_upgrade` 的版本检查与保存点，本仓将迁移与版本记录置于同一 SQLite 事务，由“保留 T01 已应用的迁移记录并拒绝比程序新的数据库版本”验证。 [权限源码](https://github.com/moodle/moodle/blob/159ab15527329473770aefdf864499ce764752af/mod/quiz/db/access.php#L51) · [升级源码](https://github.com/moodle/moodle/blob/159ab15527329473770aefdf864499ce764752af/mod/quiz/db/upgrade.php#L27)

### T03　让人从浏览器完成第一次学习

- **前置**　T02 通过。
- **交付**　提供 `pnpm run dev`，使用独立的本地演示库和预置学生会话。最薄的界面包括打开活动、选原文、预览本次交付、提交和刷新回看。界面按已发布声明显示工具和服务端进度。提交期间保留输入，结果未明可重试。
- **验证**　浏览器用例从页面实际选段并提交，刷新后核对原文片段、回执和完成状态，且不显示待评或分数。另一学生看不到该片段。将该用例接入累计验收，并在 README 写明浏览器的准备命令。
- [x] **完成条件**　项目负责人按 README 就能亲手走完第一笔业务。浏览器与 T02 的测试共用服务入口和持久化逻辑。
- **自动验收**　“浏览器拖选原文并提交，刷新可回看，另一学生读不到”先因演示入口返回 401 失败。锁定的 Chromium 目标组 `node --test tests/browser/reading.test.ts` 实跑 3 项，`pnpm run verify` 实跑 23 项。独立检出 `6943f57` 按 README 安装后同样通过 23 项，并通过 `pnpm run dev` 从空演示库开始提交、重启服务及回看相同引文和回执。Linux CI 待推送后运行。
- **质量记录**　`pnpm run coverage` 通过 23 项。阅读页脚本分支覆盖 98.55%，剩余分支是本地草稿指向缺失段落的防御处理。最高 CRAP 7.0，`dryer` 无候选，浏览器脚本 33 个变异全部被测试识别。演示启动脚本通过独立检出启动验证，未计入 LCOV。
- **人工验收**　2026-11-19 负责人按 [README 的浏览器演示](../README.md#浏览器演示)亲验通过。选段预览正确，提交后显示「活动已完成」和回执，刷新后引文与回执一致。下一项为 T04 第 ① 批发布校验。

### T04　用声明跑通完整两步阅读

- **前置**　T03 通过。
- **交付步骤与引用**　按[两步阅读样例](学习平台内核参考架构.md#两步阅读练法)发布模板、材料和受限评分键。练法声明选据与解释两个目标，分别绑定证据槽位和逐题评价单位。两步各自用有身份的位置引用同一份定版材料。同一标识和版本发布后内容固定。启动时固定教学依赖版本和首次起算时刻，记录布置的初始策略。公布范围和参与资格按当前授权复核。
- **接入内置能力**　把选区、单选和服务端选择题评估器登记到同一份内置清单。发布时核对版本、权限、输入输出类型及槽位引用，运行时按已登记的能力绑定工具。宿主显示获准输入，第一步确认后才放行第二步，刷新仍展示当初交出的引文。
- **交付交卷与评估**　第一步按两个不同段落和用途检查交付完整性。第二步引用获准的上一步提交，并为每题登记新的作答表现。交卷、完成事实和待评记录同事务落盘。服务端从同库领取任务，用固定键逐题评估。依据齐备才公布整篇计数。评阅者可读获准原答和片段，给学生的选据评语独立于分数保存。

- **核对架构交付**　在本清单的章目对照表中，为每个有首版任务的章补上实际实现文件或符号，以及终验中验证该行为的用例名。一条端到端用例可覆盖多章。只有目录、类型声明或界面截图的项仍待验证。整章后置的项保留启用条件。
- [ ] **完成条件**　负责人可以从零安装、启动、操作、关闭并恢复，并能按章查到实际交付与测试结果。Agent 可在另一份干净检出重现测试结果。勾选并保存后，对最终提交再跑同一验收命令，交接该次结果和提交号，至此首版完成。
