# 迁移与验收清单

版本：v1.0。架构切片按下列条款验收。[本仓实测与缺口](架构验收记录.md)按 AC 编号给出适用范围与证据。方框是可重复使用的核验模板。OwnClass 的行为进度依然只记在[兼容台账](迁移/兼容台账.md)。

## 1. 开始前：建立现状证据

- [ ] 阅读仓库已有 `AGENTS.md`、项目说明及适用的目录级约束；将本包条款合并到适当位置，保留不冲突的已有要求。
- [ ] 定位原架构及其引用的《在线两步阅读实施规格》、公共契约、内容校验入口、数据库迁移与提交代码。本仓实现位置见[接入说明](工程接入说明.md)，产品 DSL 资料由对应宿主提供。
- [ ] 记录当前工作区未提交修改、实际分支与可回退基线，避免覆盖其他工作。
- [ ] 沿一次真实提交追踪：宿主输入、命令验证、授权、事务、任务登记、判定、回执与恢复。
- [ ] 查明活动、作品修订、提交、判定、任务各由哪个模块写入；列出绕过公开入口的现存路径。
- [ ] 核对现有测试和可运行样例，先重用能证明行为的检查，不因本包使用新术语而重写已满足要求的实现。

本仓已按 AC 编号完成一轮[基线核对](架构验收记录.md#当前实现与验收差距)，每个判断附有现行代码、测试或缺口。后续批次沿用“已实现且有验收、已实现但缺验收、缺实现、不适用”四种状态，写清涉及的入口、证据修订和未覆盖场景。尚未检查的条目保持待核实；已经承诺的能力继续跟踪其缺口。

## 2. 迁移映射与历史真实性

先按行为判定归属，再映射字段。同名的旧 `answer` 可能分别表示可改草稿、已交原答或当前反馈，不能直接合并。

| 旧系统对象或行为 | 新模型中的候选归属 | 迁移时必须确认 |
|---|---|---|
| 文章、题目、答案键 | 内容与规则的版本引用 | 是否有可靠历史版本；当前版本不能冒充历史版本 |
| 一次练习 | 活动实例 | 学习者、发起来源、已发生状态与当前写入方 |
| `phase1`、`phase2`、轮次 | 模板步骤或步骤尝试 | 两次正式交付还是同一步重做；名称留在应用或模板层 |
| 可继续编辑的答案、笔记 | 草稿或作品修订 | 不应因为导入而自动成为正式提交 |
| 已交答案与片段 | 提交及固定作品引用 | 原答、用途、槽位、原尝试和可读范围 |
| 自动评分、教师评语、当前成绩 | 有来源的候选判定、有效判定与反馈 | 能否区分原判和改判；历史缺失须如实表示 |
| 复盘开放、重做资格 | 当前授权与教学公布策略 | 历史已经展示过的反馈与当前可读范围分别保存 |
| 错题本、复习计划 | 基于事实和规则版本的派生状态 | 是否可重建；旧口径与新口径是否一致 |

- [ ] 为导入项保留来源命名空间、原始 ID、导入批次及可追溯原始记录；定义来源唯一键，重复导入不得新增相同事实。
- [ ] 原始记录含敏感信息时按相应用途授权保存，不能把迁移日志作为无权限限制的旁路。
- [ ] 缺失的题目历史版本、揭晓时间、提示使用和判定来源标记为未知或历史导入，不填造推测值。
- [ ] 只有最终成绩的记录不能伪造出逐题判定、改判轨迹或首次独立作答事实。
- [ ] 历史导入采用有权限、可审计的迁移入口，保留原始业务时间和本次导入时间，不冒充刚发生的学生操作。
- [ ] 缺乏所需依据的记录可作历史展示，但不自动进入“首次、无提示、揭晓前”等严格指标。

## 3. 写入归属、切换与回退

**每个活动实例在任一时点只能有一个权威写入者。** 优先让新启动实例进入新内核，既有进行中实例继续由原运行时或兼容适配层处理。需要迁移进行中实例时，必须有显式交接步骤，冻结原写入、迁移状态、核对后再切换路由。

- [ ] 按实例或明确批次记录当前运行时归属及路由，避免同一实例被两个状态机独立推进。
- [ ] 旧接口通过适配层转成统一命令；原阶段字段不散布到内核条件分支。
- [ ] 默认不实施长期双写。确有双写需要时，先定义权威来源、失败补偿、去重和对账，再启用。
- [ ] 切换前验证数据库及作品附件的可恢复备份，并保留迁移脚本版本与执行批次。
- [ ] 写出回退范围：哪些流量回旧入口，哪些新实例仍需新内核继续处理，哪些新记录由兼容读取提供。
- [ ] 回退必须保留切换后已确认的提交、判定和授权变更；禁止只恢复旧库快照而丢弃新增事实。
- [ ] 内容或表结构变更采用能解释兼容范围的迁移步骤；不可逆步骤另列影响与必要决策，不由脚本静默执行。

## 4. 分阶段执行

### 阶段 A：最小接口与两步阅读

- [ ] 基于现有契约整理公开 API/SPI，附最小调用样例；是否新增 SDK 包由真实依赖决定。
- [ ] 发布两步阅读声明，完成启动、保稿、选据提交、正式作答、可靠回执、评估、连续改判、授权读取和恢复。
- [ ] 用“只交选据即完成”的声明验证无评估路径：不应生成不需要的评分任务。
- [ ] 运行本阶段涉及的 P0 验收，记录可重现结果后再扩大迁移。

### 阶段 B：旧双轮交卷的真实切片

- [ ] 固定旧行为基线，保留限时首轮、不限时后续交付、原答比较与复盘规则。
- [ ] 验证页面自由导航和草稿修改不产生正式提交；两轮记录分别固定版本、用途和揭晓情况。
- [ ] 导入一批匿名化代表样例，按相同口径核对提交、原答、成绩、状态和可见字段。
- [ ] 在有限批次切换，演练回退并验证新增学习事实仍可读取和继续处理。

### 阶段 C：按需求增加一个不同维度的样例

- [ ] 需要验证非客观评分路径时，做在线翻卡自评及复习建议；不要求同步建设完整词汇系统。
- [ ] 需要验证新作品类型时，做独立图片、文本或录音交付的小样例；不要求先建设复杂编辑器。
- [ ] 比较接入时新增和修改的文件。若必须改核心业务逻辑，说明新增的通用规则、旧实例兼容办法和验收。

离线同步、第三方代码安装、跨模板影响分析和大型报表不作为当前切片的默认任务。两种阅读路径通过，只证明对应变化方向，不能据此宣称所有扩展类型均已成熟。

## 5. 验收矩阵

优先级含义：**P0** 是当前迁移切片切换前的门槛；**P1** 是相应能力开放前的门槛，当前未启用且未承诺交付可记录不适用；**P2** 用于扩大开发者接入。优先级低不代表已启用能力可以违反契约。当前已承诺但尚未实现的能力属于缺实现，不得仅以未完成为由记为未启用或不适用；两步阅读原有的连续改判承诺仍须通过相应验收。各批次使用第 7 节的字段记录实证。P0/P1/P2 是本矩阵的优先级，OwnClass M04 的 P0–P6 是试点工序。

### 5.1 提交、判定与恢复

| ID | 场景 | 预期结果 | 优先级 |
|---|---|---|---|
| AC-01 | 相同启动操作重发 | 同一实例、同一起算时间，不重复分配尝试 | P0 |
| AC-02 | 已确认提交同操作、同内容重发，含截止后重取 | 同一提交身份；可见字段按本次权限生成，不重复计数或派发任务 | P0 |
| AC-03 | 同操作标识改交不同内容 | 明确冲突，原提交保持不变 | P0 |
| AC-04 | 两窗口用不同操作同时竞争同一交付位置 | 只产生该提交模式允许的事实数量；落败者有可解释冲突，草稿可保留 | P0 |
| AC-05 | 提交事务关键点注入失败或终止进程 | 确认、进度、必要任务全部提交或全部回滚；不出现成功回执但任务缺失 | P0 |
| AC-06 | 任务领取后、计算后、结果写入前终止进程 | 重启后可恢复或重新领取；重复完成不重复计入判定 | P0，异步评估启用时 |
| AC-07 | 同一来源的旧评分晚于获准新复评返回 | 归属原评估身份，按授权顺序与规则裁决，不按到达时间覆盖新结果 | P0，复评启用时 |
| AC-08 | 两次改判竞争同一旧修订号，再撤销当前判定 | 仅一次竞争成功；历史追加，修订号递增；按规则回落有效判定 | P0，改判启用时 |
| AC-09 | 交付后修改原作品或生成新版 | 旧提交、评阅依据和原答仍指向原版本 | P0 |
| AC-10 | 截止关闭活动，随后评估已确认提交 | 停止新交卷，不删除旧事实；获准的后续评阅与回执读取仍可进行 | P0，限时启用时 |
| AC-11 | 发布新模板、替换服务版本后恢复旧实例 | 按固定版本解释并可恢复；不静默套用新规则 | P0 |
| AC-12 | 下游引用后重做上游 | 旧绑定保持；是否要求下游重做遵守显式策略，不自动换成最新证据 | P1，步骤重做启用时 |

### 5.2 授权与作品交付

| ID | 场景 | 预期结果 | 优先级 |
|---|---|---|---|
| AC-13 | 开放复盘并读取后，再收回权限 | 已开放的题卡、回执、查询、导出、缓存与 Agent 入口均按当前范围交付；历史事实不被改写 | P0 |
| AC-14 | 仅允许整篇汇总时请求题目子集、单题分组或下钻 | 统一查询入口拒绝不获准的范围；待评结果不泄露被限制的逐题信息 | P0，盲批启用时 |
| AC-15 | 普通教师、未指派评阅者、不同受托 Agent 访问同一记录 | 按实际身份、关系、用途与当前授权裁决，不因角色名称相同而放行 | P0 |
| AC-16 | 文件上传未完成或保存失败后请求正式提交 | 不返回正式提交成功；已确认提交不指向缺失附件 | P1，文件交付启用时 |
| AC-17 | 客户端导出后改原稿，再超时重试 | 预览、评阅和重试引用同一冻结物；变更内容不能沿用已确认操作 | P1，独立交付启用时 |
| AC-18 | 客户端声明不符的 `sourceRef` 或自行声称已核验 | 来源状态由平台依据实际核验记录；独立交付不自动取得源片段证明，也不授予原稿权限 | P1，来源声明启用时 |
| AC-19 | 裁剪图旁附有全量私有工程包，或严格源片段槽位接收图片 | 未授权私有包不默认交付；不能用独立图片静默替代必需来源验证 | P1，相关类型启用时 |
| AC-20 | 同一证据多次导出、下游复用或换格式 | 导出本身不新增独立表现；真实新尝试也不因内容相同被一律去重 | P1，相关计量启用时 |

### 5.3 迁移与扩展

| ID | 场景 | 预期结果 | 优先级 |
|---|---|---|---|
| AC-21 | 同一批旧记录重复导入，中途失败后重跑 | 按来源身份去重，批次可追踪，不复制学习事实 | P0，历史导入启用时 |
| AC-22 | 旧数据缺版本、揭晓记录或改判来源 | 保持未知；对账区分迁移错误与口径变化，不捏造新指标依据 | P0 |
| AC-23 | 切换后产生新提交，再执行回退 | 实例写入归属明确；新事实不丢失，后续读取与处理路径明确 | P0 |
| AC-24 | 无评分自评活动完成并重发，重建复习建议 | 不生成客观正确率或多次推进；重建派生状态不重复发起真实活动 | P1，调度启用时 |
| AC-25 | 未参与设计的开发者或独立 Agent 仅用公开入口接入 | 记录耗时、求助、错误与改动范围；无需导入内核内部实现，结论只覆盖已测能力 | P2 |

## 6. 完成定义与验证边界

- [ ] 当前切片相关的 P0 已通过；启用的 P1 能力已通过对应检查。未执行项写明原因、影响和下一触发条件。
- [ ] 正常路径与关键故障路径均有可复现证据；不能用“一条成功端到端测试”替代事务和竞争验收。
- [ ] 对账有确定样本与同口径结果。性能只记录实测环境、负载和结果，不套用未验证的固定耗时承诺。
- [ ] 原答、作品、判定、当前权限和待评任务在恢复后相互一致；回退演练不丢切换后的事实。
- [ ] 文档中的命令、路径、错误说明与实现一致；新增能力的接入步骤已经实际执行过。
- [ ] 已有足够证据覆盖当前风险后停止无目的扩大测试，进入下一迁移切片。

## 7. 每个切片的交付报告模板

实施者复制以下字段填写，不得把计划写成完成事实：

| 字段 | 填写内容 |
|---|---|
| 切片与范围 | 本次迁移的业务、模板及排除范围 |
| 基线与变更 | 原行为依据、代码版本、变更文件及数据库迁移 |
| 模型映射 | 旧新实体对应、未知信息与导入身份 |
| 写入归属 | 切换前后负责实例的运行时和路由规则 |
| 验收结果 | AC 编号、实际命令、通过／失败／不适用及证据位置 |
| 对账结果 | 样本范围、数量与内容差异、口径差异的解释 |
| 扩展边界 | 新增接口、核心修改原因、是否使用内部入口 |
| 恢复与回退 | 实际演练步骤、结果、新增事实的保留方式 |
| 剩余事项 | 已知限制、责任与下一触发条件 |

执行入口见[仓库规则](../AGENTS.md)和[开发与验收说明](../README.md)。
